## Dependencies and release risks

- Business owns locations, orders and merchant connections. Membership chooses allowed actions and locations. Workspace choice can narrow the UI. Paired devices have a separate device grant. Server-side entitlements, tenant identity, MFA and location checks must all retain their current purpose.
- PostgreSQL is authoritative for orders, money, credentials, subscriptions, deliveries and transactional outbox events. Redis transports wakeups and holds temporary health and cache data. Event delivery cannot grant data access. Workers must recheck persisted state and use idempotent processing.
- Tenant payment connections fund merchant sales. Platform billing uses separate accounts, stores, references, callbacks, reconciliation and operator approvals. A shared verification utility may validate a signature. It must never share key lookup, settlement records or authorization across these boundaries.
- Email signup and resend queue durable work, with mailbox ownership and MFA enforced independently. The Django secret and fallbacks also protect pending verification redirects. Recovery must keep external delivery fenced until pending work is reviewed.
- Sale-time facts outlive the catalog. A restore or reporting change must retain these snapshots, paid totals, ledger relationships and unknown attribution.

Release acceptance still has several gaps. A blank platform signing secret silently enables legacy notification verification while platform checkout stays available. That compatibility behavior is documented but lacks an explicit approval gate for a new deployment. Also, the recovery verification command can pass without testing restored Django signing and redirect continuity. The heartbeat probe names a worker type and cannot distinguish replicas. The existing rotation limitation is still present. Saving a replacement tenant bundle overwrites the credentials used by older attempts, so pending work requires an approved transition procedure. None of these observations establishes a hosted incident.
